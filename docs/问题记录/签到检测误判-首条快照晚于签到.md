# 签到检测误判:今日首条快照晚于签到时刻

## 现象

2026-08-06:用户反馈"坤坤/张妈妈/爸爸都签到成功了",但仪表盘显示 ⏰ 未签到;核对后实际 **6 个账号今天全部签到**,全部误判。

## 根因

`detectSignIn()` 的基线是「今日第一条快照」:判定条件 = 最新快照存在「今日首条没有 + cycleEndTime 对日=今天+1月」的包。

但用户早上 08:42~09:30 之间签到,而首条快照(08:48)已在签到之后采集——**首条快照里已经包含签到包** → "首条没有"前提不成立 → 误判未签到。

数据实证:坤坤签到包 `cycleEndTime=2026-09-06 08:47:54`(签到于 08-06 08:47:54,UTC 00:47:54),而首条快照 00:48:13 UTC,晚于签到 19 秒。

## 修复(`src/compute/derive.js`)

基线从「今日首条」改为**「昨天最后一条快照」**:签到包只在签到当天新增,昨日最后一条不可能包含今日签到包,更稳;取不到(今日才有快照)时退化今日首条。

1. `deriveAccount()` 今日签到:取 `ts < today0` 的最后一条快照作基线
2. `gcDaySummaries()` 历史固化:同因,基线改为前一天最后一条(新增 `dayOfOffset()` 工具),取不到退化当日首条

## 验证

- 修复后 6/6 账号 `signedInToday=true`,与快照中 9/6 到期签到包(满额 100,status=0)逐一吻合
- 回归测试 7/7 通过

## 注意

- 签到推断仍依赖"元数据"(官方签到接口被 APISIX 401 拦,无法直查),本修复只解决"签到早于首条快照"场景;若官方改变签到包形态(如到期日不再对日+1月),需重校准 `detectSignIn`。
