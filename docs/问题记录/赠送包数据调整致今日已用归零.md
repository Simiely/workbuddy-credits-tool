# 官方赠送包数据调整致「今日已用」归零(消耗口径)

> **TL;DR**:今日已用不能用「今日首条剩余 − 当前剩余」——官方会**调整赠送包**(包消失/配额重置/新增包),剩余值漂移导致差值算成 0。修复:按时间扫描快照累计「已用」**正增量**(`consumeByPos`),包重置时 prev 同步回退点重新累加。v1.4.31。

## 问题

- 现象:用户报"今日刷新不出来,但其他人今日有使用"(今日已用 = 0,实际有消耗)。
- 数据库字段级证据(官方 8/5 对多账号赠送包调整):
  - 账号 0813:配额 4020→3720 的包**消失**、已用 296→0 **重置**
  - 账号 6627:08:35 已用 92→0 **重置**

## 根因

旧口径 `todayUsed = 今日首条剩余 − 当前剩余`。剩余 = 总量 − 已用,官方调整赠送包(总量变化/已用重置)让剩余值发生**非消耗性漂移**,差值可能为负或归零,消耗被算没。

## 解决(v1.4.31)

```js
// consumeByPos:按时间升序扫描快照,只累计「已用」正增量
for (const s of snaps) {
  const used = s.used ?? 0;
  if (used >= prevUsed) total += used - prevUsed; // 正常增长
  prevUsed = used;                                 // 包重置(回退)时同步回退点,重新累加
}
```

- 应用于 todayUsed / dailyUsed / series,全链路统一。
- 删除唯一剩余差口径的死字段 `consumed`(全项目零消费)。

## 验证

- 效果:张妈妈 0→77、鲁妈妈 0→74、坤坤 52→125(官方震荡致偏高,属预期)。
- 新增 `test/derive-consume.test.mjs`(9 断言),全量 7 文件 120 断言全过。

## 教训

- "剩余差"依赖剩余值连续,而剩余值会被官方数据调整打破 → 消耗必须从「已用」侧累加。
- 查"今日没数据"类问题先看**数据库原始快照**(SQLite 直接查 readings),别只看派生结果。
