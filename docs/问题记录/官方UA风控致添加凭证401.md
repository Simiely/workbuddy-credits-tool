# 官方 UA 风控致添加凭证/查询全部 401(v1.4.62 事故,2026-08-16)

> **TL;DR**:billing 接口(`/billing/meter/get-user-resource`)有 **UA 风控**,只放行特定 `Edg/xx.0.0.0` 占位版本。工具硬编码的 `Edg/148.0.0.0` 落后于官方当前版本,被 APISIX 网关 401 拦截。实测仅 `Edg/151.0.0.0` 稳定放行(148/150/151 精确版本均 401)。**全部账号突然集体 401、换账号重登无效时,优先怀疑 UA 被风控,而非凭证/session。**

## 症状与迷惑点

- GUI「添加当前账号」报 401;`wb-credits all` 全部账号凭证过期(0/N 成功)
- 在调试 Edge 里重新登录成功(页面右上角显示新账号)后依然 401 —— 排除"没登录/登错窗口"
- 页面右上角"已登录"可能是 SPA 缓存假象:session cookie 已死后页面仍显示登录态,刷新后依旧;必须直接请求接口实测

## 排查链(从现象到根因,供复现)

1. **三层状态**:GUI(8080)`/api/status` daemon:"ok"、daemon(8129)`connected:true`、Edge 调试端点(9222)有响应 → 排除链路断
2. **cookie 端到端**:`Network.getCookies` 取调试 Edge 的 workbuddy.cn cookie → 组装 `Cookie` 头 POST billing API → **401**
   - ⚠️ targetId 随页面刷新/登录变化,必须实时 `GET /tabs` 取当前 ID,否则拿到 0 个 cookie 误判
3. **页面内 fetch 对照**(决定性):在 workbuddy.cn 页面上下文直接 `fetch(API, {method:'POST', body:'{}'})` → **200 + code:0 真实数据**
   - 结论:浏览器环境 cookie 鉴权有效,非官方改版、非 session 过期
4. **请求头对照**:Node 进程带 Origin / Referer / X-Requested-With 等组合 → 全部 401 → 排除 CSRF/同源校验
5. **UA 多版本循环测试**(定位):同一 cookie,循环换 UA 请求 → 命中规律:

| UA(Edg 部分) | HTTP |
|---|---|
| 148.0.0.0(工具原值) | 401 |
| **151.0.0.0** | **200(重复 3 次稳定)** |
| 151.0.4129.78(真实精确版) | 401 |
| 150.0.0.0 | 401 |

## 修复

`src/config.js` 的 `UA` 常量改为放行值:

```js
export const UA =
  "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/151.0.0.0 Safari/537.36 Edg/151.0.0.0";
```

改后重启 GUI 生效(CLI 为独立进程,读新配置即生效)。验证:临时脚本 import `src/compute/client.js` 的 `fetchCredits` 喂调试 Edge cookie,成功返回 Accounts/Uin 即修复。

## 官方再次改版时如何实测新放行值

```bash
# 取当前调试 Edge 的 workbuddy.cn cookie 组装 $COOKIE 后,循环换 UA:
for ua in "Chrome/152.0.0.0 Safari/537.36 Edg/152.0.0.0" "Chrome/153.0.0.0 Safari/537.36 Edg/153.0.0.0"; do
  curl -s -o /dev/null -w "%{http_code}\n" -X POST https://www.workbuddy.cn/billing/meter/get-user-resource \
    -H "Content-Type: application/json" -H "Cookie: $COOKIE" \
    -H "User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) $ua" -d "{}"
done
# 找到 200 的主版本 → 更新 src/config.js,并同步本机 D:\Tool 运行实例
```

## 关联坑(同次事故)

- **调试 Edge 必须存活**:采集只读调试实例(独立 profile `edge-debug-profile`)登录态;实例被关 → daemon `connected:false` → "浏览器代理未连接"。日常 Edge 登录无效。
- **USER_DATA 硬编码**:v1.4.62 的 `edge-daemon.mjs` 硬编码打包机路径 `C:\Users\2504\...`,已修为 `os.homedir()` 动态获取。旧包 grep 到具体用户名路径即需同步。
- **凭证统一到期**:session 有固定有效期,账号池凭证可能同批到期(显示"凭证过期"),属正常机制,需在调试 Edge 重登后续期。
