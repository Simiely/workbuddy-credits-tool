# 官方签到接口直连 401 → 改元数据推断签到(v1.4.33)

> **TL;DR**:WorkBuddy 签到接口(`/billing/meter/check-gift-claimed`、`claim-gift`)在官方前端 JS bundle 里能找到,但**直连被 APISIX 网关 401 拦截**。改纯元数据推断:签到 = 最新快照新增一个「到期日 = 领取日 + 1 自然月(对日)」的赠送包。`detectSignIn()`。

## 问题

- 需求:账号每日签到领积分(第 1-6 天 100 分/天、第 7 天 1000 分),卡片标记"已签到"。
- 调研:usercenter JS bundle 中找到官方接口,但直连报 401(APISIX 拦,缺内部签名)。

## 换角度(用户思路)

签到会领 100 积分 → 元数据必有痕迹。实证(0813 今日 08:50):

- 包数 46→47(新增一个 100/100 **满额**包)、配额 +100
- 新包 `cycleEndTime`(**字段小写**)= 领取日 + 1 自然月对日:8/5 签到 → 9/5 到期;8/4 → 9/4

## 实现(v1.4.33)

`detectSignIn(firstPacks, lastPacks, todayKey)`:最新快照存在「今日首条没有 + cycleEndTime 对日 = 今天+1 自然月」的包 = 已签到。

- **对日匹配**防昨天签到包误判
- **不要求满额**防签到后消耗导致漏判
- **对比今日首条**防本来就存在的包误报
- deriveAccount 输出 `signedInToday`;前端卡片今日消耗行加 ✅已签到/⏰未签到 徽标(`.sign-badge`)
- day_summary 加 `signedIn` 列(ALTER 迁移),固化时记录 → 历史签到可回查

## 验证

- 新增 `test/signin-detect.test.mjs`(7 断言);真实数据 6 账号 5 签 1 未签,全部正确。

## 备选(若官方直充)

本方案依赖"签到以独立满额包入账"这一规律。若官方改为直接加配额(无新包),需改用官方接口 `check-gift-claimed`(需解决 APISIX 鉴权)或观察其他元数据字段。
