# 架构说明

> WorkBuddy 积分工具 · 完整架构(v1.4.24)。CLI 与 GUI 双入口,共享 `src/` 分层;浏览器仅在"添加账号"时需要。
> 更新记录:2026-08-04 重写(v1.3.x 的 `lib/` 共享层已并入 `src/`,前端 4 文件 → 7 文件,告警/凭证过期/耗尽预测已下线)。

## 一、目录结构

```
workbuddy-credits-tool/
├── wb-gui.mjs          # GUI 服务:HTTP + 路由表 + 分发层 + 启动(含文件地图注释:A 基础设施/B 路由表/C 分发层/D 启动)
├── wb-gui.html         # 前端页面结构 + 样式(引用 7 个 classic script,带 ?v= 版本戳)
├── wb-gui.state.js     # 前端①共享状态/常量/helper(37 行)
├── wb-gui.core.js      # 前端②api()/弹窗/管理员三态(218 行)
├── wb-gui.render.js    # 前端③渲染:hero/卡片/账号总览/到期柱图(216 行)
├── wb-gui.chart.js     # 前端④趋势柱状图/每日窗口/图例/模式切换(v1.4.22 拆出)
├── wb-gui.ops.js       # 前端⑤账号操作:排序/改名/删除/添加/导出/清空
├── wb-gui.sync.js      # 前端⑥WebDAV 云同步
├── wb-gui.actions.js   # 前端⑦刷新编排/自动刷新/SSE/启动接线(唯一副作用启动段,最后加载)
├── wb-credits.mjs      # CLI 入口:命令分发 + 薄调用(只读查询,不落盘)
├── edge-daemon.mjs     # 浏览器代理(独立进程,CDP WebSocket,HTTP API 8129 / Edge 调试 9222)
├── src/
│   ├── config.js       # 集中常量 + 环境变量(WB_COLLECTOR 采集方案、端口等)
│   ├── domain.js       # 实体词汇表 typedef
│   ├── collect/        # 采集方案工厂:edge(CDP)/ file(文件+WebDAV),由 WB_COLLECTOR 或平台决定
│   ├── compute/        # 业务核心(10 模块):client/model/query/store/history/derive/sample/scheduler/webdav/account-ops
│   ├── store/          # SQLite 唯一真相源(db.js,单例 + 自动迁移 + WAL)
│   └── present/        # 渲染输出(CLI markdown/CSV)
├── test/               # 回归测试(npm test 一键跑):admin-flow/history-import/render-lines/server-routes + helpers/vm-env
├── Dockerfile / docker-compose.yml / .dockerignore   # 容器部署(P5)
├── docs/               # 架构/部署/交接/审计 + 问题记录(一坑一篇)
└── legacy/             # 历史一次性脚本/旧前端(留档)
```

前端 7 个 classic script 加载顺序(即依赖方向):`state → core → render → chart → ops → sync → actions`。
无打包器,靠顶层 `const/let/function` 共享全局词法作用域;共享状态集中在 `wb-gui.state.js`。

## 二、后端分层(依赖方向自上而下)

```
src/collect/* ──► src/compute/query ──► src/compute/client(HTTP) ──► www.workbuddy.cn 内部接口
                      │
                      ▼
              sample.sampleAll ──► appendSnapshot ──► src/store/db(readings 时序表,append-only)
                      │
                      ▼
              derive(纯函数,读 readings)──► /api/dashboard/all ──► 前端展示
                      │
              scheduler(自适应间隔 + SSE 广播)──► 调 sampleAll
```

| 模块 | 职责 | 说明 |
|---|---|---|
| `src/collect/*` | 采集方案工厂 | `WB_COLLECTOR=edge`(Edge CDP)/ `file`(文件+WebDAV);win32 默认 edge,其余 file |
| `src/compute/client.js` | 内部接口 HTTP 客户端 | IPv4 强制、超时、凭证失效错误类型 |
| `src/compute/model.js` | 唯一解析口径 | 原始响应 → 标准化 summary |
| `src/compute/query.js` | 查询编排 | 批量并发(6)/单账号容错/lastStatus 持久化 |
| `src/compute/store.js` | 账号池读写 | loadAccounts/saveAccounts/addOrUpdateAccount(按 Uin 去重) |
| `src/compute/history.js` | 时序 + 缓存 | appendSnapshot(支持原始时间戳、同分钟去重)/ historyFor / 合并导入 |
| `src/compute/derive.js` | 派生纯函数(单派生源) | currentRemain/todayUsed/dailyUsed/series/近1·2·3·7天过期/expiryTier;前端只读派生结果,不自己算 |
| `src/compute/sample.js` | **唯一采样入口** | `sampleAll({onSampled})` = 采集→快照→落盘;手动刷新(/api/all)与调度器(scheduler)都走它 |
| `src/compute/scheduler.js` | 自适应调度 + SSE 广播 | 周期调 sampleAll,维护 lastCount/lastError |
| `src/compute/webdav.js` | WebDAV 云同步 | Basic Auth、多级 MKCOL、上传/下载(历史为**合并导入**,不破坏本地) |
| `src/compute/account-ops.js` | 添加账号 | 读 cookie→校验→入池(与采集层解耦) |
| `src/store/db.js` | SQLite 单例 | readings 时序表 + 迁移 + WAL |
| `src/present/render.js` | CLI 渲染 | markdown/CSV/报表 |

> 历史遗留:告警(`alerts.js`)、凭证过期展示、耗尽预测(`dailyRate/daysToEmpty`)已于 v1.4.13/v1.4.15 **全量下线**(前端零引用确认后删除),派生层只输出前端真正消费的字段。

## 三、数据流

### 采样(唯一入口,手动/定时共用)
```
手动刷新 /api/all 或 调度器 scheduler.runOnce
  └─► sample.sampleAll({ onSampled })
        ├─ query.fetchAllAccounts(实时查询全部账号)
        ├─ buildSnapshotEntry(汇总口径 + 赠送包子账号列表)
        └─ appendSnapshot(写入 readings 时序表,同分钟去重)
```

### 派生与展示(读写分离)
```
/api/dashboard/all
  └─ derive(读 readings)──► per[]: currentRemain/used/todayUsed/dailyUsed/series/expiring1·2·3·7d
        └─► 前端:hero 卡(今日 vs 昨日)、账号卡片、总览表格、趋势柱状图(每组 + 当日合计柱)
```

### 添加账号(唯一需要浏览器的一步)
```
Edge 登录 → save-current / GUI「＋添加当前账号」
  └─► account-ops ──► cookies(经 edge-daemon 读 cookie) + client.probeAccount(校验+探测 Uin)
        └─► store.saveAccounts(按 Uin 去重)
```

## 四、账号池字段(wb-accounts.json)

| 字段 | 说明 |
|---|---|
| `id` | 唯一标识(`acc` + 时间戳 base36) |
| `name` / `displayName` | 原始名称 / 显示名称(用户自定义) |
| `uin` | 腾讯云账号标识(去重键) |
| `cookieHeader` | 登录凭证(Cookie 请求头,🔴 敏感) |
| `lastStatus` | `ok` / `error` |
| `addedAt` / `updatedAt` | 时间戳 |

## 五、接口一览(GUI)

`/api/status /api/accounts /api/all /api/last /api/derived /api/history?account= /api/dashboard/all /api/save-current /api/rename /api/del /api/reorder /api/export.md /api/clear-data /api/scheduler/run /api/scheduler/status /api/webdav/config|test|upload|download /api/admin/status|setup|verify|clear /api/stream(SSE)`。

路由登记制(见 `wb-gui.mjs` 文件地图 B 段):全部端点一张 `routes` 表(method+path 精确匹配),管理员鉴权统一在分发层按 `route.admin` 拦截,handler 不重复鉴权。

## 六、维护指南

### 新增/修改功能
1. **后端业务** → 改 `src/compute/` 对应模块;**前端展示** → 按职责改 7 个文件之一(渲染→render.js,趋势→chart.js,交互→actions.js,账号操作→ops.js,同步→sync.js)
2. **新增接口** → 只在 `wb-gui.mjs` 路由表加一项(写类加 `admin:true`)
3. **改前端**刷新页面即可(实时读文件 + `?v=` 版本戳强制刷新);**改后端**需重启服务
4. **前端文件清单改动**(增删 script)必须同步 4 处:`wb-gui.html` 引用、`wb-gui.mjs` 静态路由、`test/server-routes.test.mjs` 复制正则+断言、`test/helpers/vm-env.mjs` 文件列表

### 改版后必须验证
```bash
npm test                # 4 个测试文件、90+ 断言(管理员/历史导入/趋势/路由冒烟)
node --check wb-gui.mjs # 语法校验
```

### 常见问题
| 现象 | 处理 |
|---|---|
| 查询报"查询失败" | cookie 失效(约 7 天),重新登录后 `save-current` 更新 |
| save-current 报"代理未运行" | 启动 `edge-daemon.mjs`;GUI 首页有醒目提示 |
| GUI 打不开 | 检查 8080 被占(自动顺延,看日志) |
| 页面显示旧版 | Ctrl+Shift+R 硬刷新(版本戳已 bump) |
| 测试红 | 前端文件清单 4 处同步点是否漏(见上) |

## 七、风险与限制

- **内部接口无公开文档**:官方改版需同步 `src/compute/client.js`
- **凭证敏感**:`wb-accounts.json` / `wb-sync.json` / `wb-admin.json` / `credits.db` 严禁外传(已 gitignore)
- **采集频率**:批量并发 6,属低频访问;勿大幅提高并发
- **云同步为明文传输**:建议 WebDAV 地址使用 https
