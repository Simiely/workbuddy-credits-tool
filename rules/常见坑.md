# 常见坑 · 详细记录

> AGENTS.md 的 @引用文件。按"越具体越好"原则记录,同项目的完整版本见 `docs/问题记录/`(一坑一篇,含 TL;DR)。

## 1. GUI 前端改完要重启?(不用,但容易混淆)

- GUI 服务对 `wb-gui.html` / `wb-gui.js` 是**每次请求实时读文件**,改前端刷新浏览器页面即生效
- 改 `wb-gui.mjs` / `lib/*` / `edge-daemon.mjs` 等后端代码**必须重启服务**
- 忘记重启 → "改了没生效"的假象,先分清改的是前端还是后端

## 2. 浏览器缓存旧 JS / 跨域被拦

- GUI 所有响应带 `Cache-Control: no-store`(防旧 JS)+ CORS 头(演示预览页等跨域端口可访问)——**不要删**
- 症状:页面行为与代码不符(如刷新按钮一直转)、请求被浏览器拦截
- 处理:先试普通刷新;仍不对再查 Console 报错

## 3. "总量/剩余"口径 = 体验版 + 赠送

- 所有涉及总量的地方(折线、条形、卡片、消耗历史、明细卡)必须 `总剩余 = 体验版剩余 + 赠送剩余`,`累计已用 = 体验版已用 + 赠送已用`
- 后端:`lib/history.js` 的 `historyFor` / GUI `/api/dashboard/all` 已统一;老快照无 `baseUsed` 字段时按 0 兼容
- 前端别再用"只算赠送"的旧口径

## 4. 刷新按钮无限转圈(请求挂起)

- 任何请求都要有超时:服务端 `fetchCredits` 单账号 **8s**(`FETCH_TIMEOUT_MS`),前端 `refreshAll` 整体 **12s**
- 按钮状态**单点控制**(`setBusy`/loading 标志),`finally` 必须恢复——结构上杜绝卡死
- 失败时自动显示"已显示上次数据",不白屏

## 5. 历史快照:同分钟去重 + 时间升序

- `appendSnapshot` 同账号同分钟去重(键 = ISO 分钟),避免手动+自动刷新刷爆历史
- 读取历史后**必须按时间升序排序**(`historyFor` / dashboard 已做),否则折线方向颠倒
- 快照只记摘要(剩余/已用),不存完整明细(明细以 `wb-last-data.json` 为准)

## 6. 添加账号的手机号要从 workbuddy 页面读

- `phoneFromPage` 必须定位到 **workbuddy 页面**再提取手机号(曾因固定读浏览器第 1 个标签页而读错/读空)
- 添加账号链路:`getEdgeCookies` → `probeAccount`(校验+探 Uin)→ 按 Uin 去重入池

## 7. WebDAV 中文目录

- 备份目录 `workbuddy/workbuddy积分` 需**逐级 MKCOL**(每级 201/405/301 视为成功)
- 中文目录名:客户端按 URL 编码发送是标准做法,真实 WebDAV 会正确解码;本地 mock 测试服务器若不解码,是测试端限制,不是 bug
- 密码存本机 `wb-sync.json`,API 不返回明文

## 8. Windows 环境坑

- Node 在 Windows 上跑 CLI,`/tmp/xx` 会被解析成 `C:\tmp\xx`——测试传路径用 Windows 风格(`D:/...`)
- git push github 443 超时:全局 gitconfig 若有 `http.https://github.com.proxy=`(空值)会强制直连(被墙),push 时显式指定代理即可:
  `git -c http.https://github.com.proxy=http://127.0.0.1:7890 -c http.sslVerify=false push ...`

## 9. 内部接口无公开文档

- `lib/workbuddy.js` 的地址/参数/字段可能随官方前端改版变化;改版后接口 401 或字段缺失时先查这里
- 兜底方案:legacy 中的 CDP 浏览器采集思路

## 10. edge-daemon 连不上浏览器:DevToolsActivePort 残留文件(已修)

- **现象**:edge-daemon 一直 `connected:false`,日志停在 `connecting ws://.../devtools/browser/<旧uuid>` 后挂起(连超时都不触发)。
- **根因**:旧实现读 `Edge User Data/DevToolsActivePort` 文件发现调试端点。该文件可能**残留旧实例的 uuid**(Edge 新实例启动后不总是重写它)——daemon 拿着失效路径连接一个不存在的 WebSocket,永不返回。
- **修复(v1.0.3)**:改用**标准 CDP 发现机制**——轮询 `GET http://127.0.0.1:<debugPort>/json/version` 拿真实 `webSocketDebuggerUrl` 再连接(debugPort 默认 9222,可 `EDGE_DEBUG_PORT` 或 argv[3] 覆盖)。端口 8129(HTTP API)与 9222(调试)分离。
- **预防**:任何"读浏览器状态文件"的逻辑都不可靠,浏览器自身 HTTP 端点(/json/version)才是权威;另注意改 lib/util.js 端口后**需重启常驻子进程**(模块加载时读值,改文件不生效)。

## 11. 今日已用/聚合类指标被"中途加账号"污染

- **现象**:今日已用恒为 0——原算法用全账号聚合 totals 的"今日最早−最新",当天新加账号让总量跳增(4227→28898),差值变负。
- **修复(v1.0.7)**:按**每账号 series** 分别算(该账号今日最早−最新总剩余,>0 计入再求和),新账号只贡献自身消耗。
- **预防**:任何"增量/消耗"类指标,聚合总量会因集合成员变化而失真——**先按最小稳定单元(账号)算,再汇总**。

## 12. 不要补丁套补丁:优先标准机制

- **现象**:操作条换行 → 加 `flex:1` 占位 → 还换行 → 又加 `nowrap`(补丁叠补丁,还不解决)。
- **修复(v1.0.12)**:结构重做——左组/右组各自 flex 容器,`margin-right:auto` 弹性两端对齐(flexbox 原生),无中间占位元素;单行靠 `nowrap + overflow-x:auto`(合理兜底)。
- **预防**:布局/逻辑问题先找**标准机制**(flex 分组、grid、margin auto),不要用占位元素/魔法数字硬凑;改布局先改结构,再改样式。
