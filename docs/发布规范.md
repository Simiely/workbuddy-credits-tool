# 发布规范（发包要求 · 2026-08-06 定）

> 以后每次发包,**只发两个版本:平台版 + exe 版**。不再有其他形态。

| 版本 | 形态 | 内容 | 发布位置 |
|---|---|---|---|
| **平台版** | tools-center 托管包(zip) | tool.json + 源码 + src/ + Docker 文件 + docs + 平台部署说明 | 存桌面 `E:\desktop\workbuddy-credits-tool-平台版-vX.Y.Z.zip`;源码即 GitHub 仓库 |
| **exe 版** | Windows 单文件(SEA,~83MB) | 内置 GUI(8080)+ edge-daemon(8129),数据在 exe 同目录 | 本地发布目录 `D:\workbuddy\2026-08-06-08-42-26\积分监控\WorkBuddy-Credits-Monitor.exe` |

**exe 不上传 GitHub Release**(体积大),需要者从源码 `build-sea.mjs` 本地构建。

---

## 一、发布前检查(必过)

1. `npm test` 全绿(7 文件)
2. 全账号归属校验:逐个账号查询,接口返回 Uin == 登记 Uin(防串号)
3. 签到显示与实际一致(元数据推断)
4. 本地实例(exe @ 8080)运行正常:`/api/dashboard/all` 返回 6 账号

## 二、版本号(顺手 bump 到同号)

| 位置 | 改法 |
|---|---|
| `CHANGELOG.md` | 顶部加 `## vX.Y.Z (日期) · 摘要` |
| `wb-gui.html` | 全部 `?v=` 戳 → `vX.Y.Z`(一次 bump 新号,勿复用旧号) |
| `wb-gui.render.js` | footer 版本号 → `vX.Y.Z` |
| `package.json` | `"version": "X.Y.Z"` |

## 三、发布步骤

```bash
# 1. 提交并推送
git add -A && git commit -m "feat: vX.Y.Z ..."
git -c http.https://github.com.proxy=http://127.0.0.1:7890 -c http.sslVerify=false push origin main

# 2. 打 tag 并推送
git tag vX.Y.Z
git -c http.https://github.com.proxy=http://127.0.0.1:7890 -c http.sslVerify=false push origin vX.Y.Z

# 3. GitHub Release(无 exe 资产;描述两个版本)
#    用 Python urllib + git credential 取 token(api.github.com curl -x 会 000;资产上传须 multipart,但 exe 不传)

# 4. 重建 exe 并更新发布目录
cd sea-build && node build-sea.mjs
cp WorkBuddy-Credits-Monitor.exe ../积分监控/

# 5. 重打平台版 zip 存桌面(自动预填 WebDAV 配置,上传零输入)
node pack-platform.mjs    # 读本机 wb-sync.json → 预填 → zip 到 E:\desktop
```

> 平台版 zip 打包要点:`pack-platform.mjs` 自动完成——复制代码 + **预填 `wb-sync.json`**(WebDAV 配置,与桌面版同一套)+ 生成 `平台部署说明.md` + 顶层结构 zip;**不含** credits.db 等数据。配置要求清单见 `docs/配置要求.md`。

> **zip 条目目录分隔符必须用正斜杠 `/`**(zip 规范 APPNOTE 强制):`pack-platform.mjs` 已遵守,勿手工"右键压缩"替代;若手工打包,条目名写成 `lib/x.js` 而非 `lib\x.js`。反斜杠打包会被 Linux unzip 判为警告(exit=1),平台 v0.12.1 前会误报"解压失败"(2026-08-06 实测事故,详见 tools-center `docs/使用指南.md`「十·一」)。打包后自检:`unzip -l` 或 `python -c "import zipfile; [print(i.filename) for i in zipfile.ZipFile('x.zip').infolist()]"`,条目名出现 `\` 即不合格。

## 四、铁律(勿犯)

- 数据文件(`credits.db*`、`wb-*.json`、备份 `credits.db.bak*`)一律不进 git / 不进包
- 平台版"工具目录即数据目录":**删工具 = 删数据**,发布说明里必须提醒先 WebDAV 备份
- cookie 更新只在桌面版做,平台版靠「云同步下载」
- 发布前先本地调试验证,不推半成品(用户偏好)
