## 1. 项目是什么

多账号采集 WorkBuddy 积分并可视化。核心洞察:**积分包本身静态(总量/到期不变),变化的是"消耗"**——系统围绕"剩余积分变化"建模(历史快照 + 折线趋势 + 今日已用/到期预警)。

- 仓库:`Simiely/workbuddy-credits-tool`(public)
- 当前版本:**v1.0.14**(CHANGELOG 有完整记录)
- 技术:Node ≥18 原生 ESM,**零第三方依赖**;前端原生 HTML/CSS/JS,无框架
- 双入口:CLI(`wb-credits.mjs`)+ GUI(`wb-gui.mjs`),共享 `lib/` 11 个模块

## 5. 常用命令

```bash
# GUI(独立实例,当前 8080)
node wb-gui.mjs                    # 8080;端口被占自动顺延 ≤8090

# CLI
node wb-credits.mjs accounts       # 账号池列表
node wb-credits.mjs all            # 批量查询全部账号
node wb-credits.mjs save-current   # 把当前 Edge 登录账号存入账号池
node wb-credits.mjs rename <key> <名> / del <key>

# edge-daemon(仅添加账号需要;工具中心已托管 8129)
node edge-daemon.mjs 8129

# Edge 调试模式启动(daemon 连接前提)
msedge.exe --remote-debugging-port=9222 https://www.workbuddy.cn/profile/plans-usage

# 语法校验(改动后必跑)
node --check wb-credits.mjs && node --check wb-gui.mjs && node --check wb-gui.js
```

## 7. 核心约定(动了会坏,务必遵守)

1. **总剩余口径 = 体验版基础用量 + 赠送积分**,前端/后端/历史快照/仪表盘必须一致
2. **子路径挂载**:`__BASE__`(工具中心注入或自行检测),所有 API 用 `__BASE__ + "/api/.."`,资源用相对路径;独立运行 `__BASE__=""` 行为不变
3. **daemon 发现**:轮询 `GET :9222/json/version` 取 `webSocketDebuggerUrl`(勿改回读 DevToolsActivePort 文件,那是旧坑)
4. 前端 `wb-gui.html/js` **每次请求实时读文件** → 改前端刷新页面即可,无需重启;改 `wb-gui.mjs`/`lib/*` 才需重启
5. 刷新超时:服务端单账号 8s、前端 12s;按钮状态单点控制(`setBusy`),`finally` 必恢复
6. **不要补丁套补丁**:布局/逻辑优先用标准机制(如 flex wrap + 固定列数),不要中间占位元素硬凑
7. **凭证安全**:`wb-accounts.json`/`wb-sync.json` 严禁上传,gitignore 已有;push 前确认 `git status` 无数据文件
