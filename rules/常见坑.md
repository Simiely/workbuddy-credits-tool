# 常见坑 · 详细记录

> AGENTS.md 的 @引用文件。按"越具体越好"原则记录,同项目的完整版本见 `docs/问题记录/`(一坑一篇,含 TL;DR)。

## 1. GUI 前端改完要重启?(不用,但容易混淆)

- GUI 服务对 `wb-gui.html` / `wb-gui.state.js` / `wb-gui.core.js` / `wb-gui.render.js` / `wb-gui.actions.js` 是**每次请求实时读文件**,改前端刷新浏览器页面即生效
- 改 `wb-gui.mjs` / `src/*` / `edge-daemon.mjs` 等后端代码**必须重启服务**
- 忘记重启 → "改了没生效"的假象,先分清改的是前端还是后端

## 2. 浏览器缓存旧 JS / 跨域被拦

- GUI 所有响应带 `Cache-Control: no-store`(防旧 JS)+ CORS 头(演示预览页等跨域端口可访问)——**不要删**
- 症状:页面行为与代码不符(如刷新按钮一直转)、请求被浏览器拦截
- 处理:先试普通刷新;仍不对再查 Console 报错

## 3. "总量/剩余"口径 = 体验版 + 赠送

- 所有涉及总量的地方(图表(柱状)、条形、卡片、消耗历史、明细卡)必须 `总剩余 = 体验版剩余 + 赠送剩余`,`累计已用 = 体验版已用 + 赠送已用`
- 后端:`src/compute/history.js` 的 `historyFor` / GUI `/api/dashboard/all` 已统一;老快照无 `baseUsed` 字段时按 0 兼容
- 前端别再用"只算赠送"的旧口径

## 4. 刷新按钮无限转圈(请求挂起)

- 任何请求都要有超时:服务端 `fetchCredits` 单账号 **8s**(`FETCH_TIMEOUT_MS`),前端 `refreshAll` 整体 **12s**
- 按钮状态**单点控制**(`setBusy`/loading 标志),`finally` 必须恢复——结构上杜绝卡死
- 失败时自动显示"已显示上次数据",不白屏

## 5. 历史快照:同分钟去重 + 时间升序

- `appendSnapshot` 同账号同分钟去重(键 = ISO 分钟),避免手动+自动刷新刷爆历史
- 读取历史后**必须按时间升序排序**(`historyFor` / dashboard 已做),否则趋势方向颠倒
- 快照只记摘要(剩余/已用),不存完整明细(明细以 `wb-last-data.json` 为准)

## 6. 添加账号的手机号要从 workbuddy 页面读

- `phoneFromPage` 必须定位到 **workbuddy 页面**再提取手机号(曾因固定读浏览器第 1 个标签页而读错/读空)
- 添加账号链路:`getEdgeCookies` → `probeAccount`(校验+探 Uin)→ 按 Uin 去重入池

## 7. WebDAV 中文目录

- 备份目录 `workbuddy/workbuddy积分` 需**逐级 MKCOL**(每级 201/405/301 视为成功)
- 中文目录名:客户端按 URL 编码发送是标准做法,真实 WebDAV 会正确解码;本地 mock 测试服务器若不解码,是测试端限制,不是 bug
- 密码存本机 `wb-sync.json`,API 不返回明文

## 8. Windows 环境坑

- Node 在 Windows 上跑 CLI,`/tmp/xx` 会被解析成 `C:\tmp\xx`——测试传路径用 Windows 风格(`D:/...`)
- git push github 443 超时:全局 gitconfig 若有 `http.https://github.com.proxy=`(空值)会强制直连(被墙),push 时显式指定代理即可:
  `git -c http.https://github.com.proxy=http://127.0.0.1:7890 -c http.sslVerify=false push ...`

## 9. 内部接口无公开文档

- `src/compute/client.js` 的地址/参数/字段可能随官方前端改版变化;改版后接口 401 或字段缺失时先查这里
- 兜底方案:legacy 中的 CDP 浏览器采集思路

## 10. edge-daemon 连不上浏览器:DevToolsActivePort 残留文件(已修)

- **现象**:edge-daemon 一直 `connected:false`,日志停在 `connecting ws://.../devtools/browser/<旧uuid>` 后挂起(连超时都不触发)。
- **根因**:旧实现读 `Edge User Data/DevToolsActivePort` 文件发现调试端点。该文件可能**残留旧实例的 uuid**(Edge 新实例启动后不总是重写它)——daemon 拿着失效路径连接一个不存在的 WebSocket,永不返回。
- **修复(v1.0.3)**:改用**标准 CDP 发现机制**——轮询 `GET http://127.0.0.1:<debugPort>/json/version` 拿真实 `webSocketDebuggerUrl` 再连接(debugPort 默认 9222,可 `EDGE_DEBUG_PORT` 或 argv[3] 覆盖)。端口 8129(HTTP API)与 9222(调试)分离。
- **预防**:任何"读浏览器状态文件"的逻辑都不可靠,浏览器自身 HTTP 端点(/json/version)才是权威;另注意改 src/config.js 端口后**需重启常驻子进程**(模块加载时读值,改文件不生效)。

## 11. 今日已用/聚合类指标被"中途加账号"污染

- **现象**:今日已用恒为 0——原算法用全账号聚合 totals 的"今日最早−最新",当天新加账号让总量跳增(4227→28898),差值变负。
- **修复(v1.0.7)**:按**每账号 series** 分别算(该账号今日最早−最新总剩余,>0 计入再求和),新账号只贡献自身消耗。
- **预防**:任何"增量/消耗"类指标,聚合总量会因集合成员变化而失真——**先按最小稳定单元(账号)算,再汇总**。

## 12. 不要补丁套补丁:优先标准机制

- **现象**:操作条换行 → 加 `flex:1` 占位 → 还换行 → 又加 `nowrap`(补丁叠补丁,还不解决)。
- **修复(v1.0.12)**:结构重做——左组/右组各自 flex 容器,`margin-right:auto` 弹性两端对齐(flexbox 原生),无中间占位元素;单行靠 `nowrap + overflow-x:auto`(合理兜底)。
- **预防**:布局/逻辑问题先找**标准机制**(flex 分组、grid、margin auto),不要用占位元素/魔法数字硬凑;改布局先改结构,再改样式。

## 13. 容器/不同时区机器部署:自然日与时间显示错位

- **现象(v1.4.29/30)**:Docker 容器部署后——趋势图缺某天(8/3 被算成 8/2)、今日已用异常(800 多)、页面左上角时间显示 8/4 16:47(实际本地 8/5 00:47);Windows 桌面(+8)全对,形成"edge 对、docker 错"。
- **根因**:docker 容器(node:alpine)默认 **UTC**。`new Date().toLocaleString()` 与 `getFullYear/getMonth/getDate` 都依赖**进程时区**,容器里自然日/显示时间整体偏移 +8 小时。
- **修复(v1.4.29/30)**:所有自然日计算(derive 的 `dayKeyOf/startOfToday/deriveGiftExpiry`)与时间显示(`cnNow()`:wb-gui.mjs、present/render.js)**固定中国时区(+8)**,与部署环境无关;Dockerfile/docker-compose 加 `TZ=Asia/Shanghai` 双保险。
- **预防**:涉及"自然日/日期/时间显示"的代码一律用固定 +8 的辅助函数,禁止直接依赖进程时区;新增此类逻辑时在 `TZ=UTC node -e` 下验证一遍。

## 14. 备份剥离 giftPackages 会坑包级口径(v1.4.47 修)

- **现象**:同步/下载恢复后今日已用被放大(2026-08-08 实测 321→1169),累计也偏大。
- **根因**:v1.4.32 备份瘦身"只保留最新一组 giftPackages";v1.4.43 包级口径 `consumeByPack` 需要**每天首末快照**的 giftPackages,首条无包 → 降级增量口径(把失效包消耗计入)。
- **修复(v1.4.47)**:`exportLegacy` 改为**每天保留首末快照组,中间剥离**;体积几乎不变。
- **预防**:改剥离策略前先确认 consumeByPack 的数据依赖;已剥离的数据无法自愈,需从完整源重新导出+导入。

## 15. 清空账号池 ≠ 删除传播(v1.4.48 修)

- **现象**:「清空本地数据」后点一键同步 → 云端账号被清空(事故)。
- **根因**:v1.4.46 的 `/api/clear-data` 对全部账号写墓碑 → 同步合并把远端旧账号全删 → 上传空库覆盖云端。
- **修复(v1.4.48)**:清空账号池**不写墓碑**(仅 `/api/del` 单账号删除写);同步加**清空保护**(远端有账号+合并后本地为空 → 拒绝上传)。
- **预防**:"本地重置"类操作(清空/重置)绝不写墓碑;"删除"类操作(单账号删除)才写。

## 16. 同步/测试前端超时(v1.4.49 修)

- **现象**:一键同步/自动同步在慢速穿透(DDNSTO)下前端报「请求超时(15s)」,但后端实际已完成。
- **根因**:前端 `api()` 默认 15s 超时;同步链路=下载(60s)+合并+导出+上传(60s);后端 handler 不随前端断开取消。
- **修复(v1.4.49)**:`syncAct` 按动作放宽——sync=90s、test=30s。
- **预防**:新增长耗时后端接口,前端调用必须显式传 timeout(参考 `/api/all` 30s、sync 90s)。

## 17. 前端时区分析:浏览器时区 ≠ 进程时区

- **现象**:曾误判"前端本地时区要改成 +8"(实际用户浏览器 +8 与后端 +8 自洽)。
- **根因**:前端跑在浏览器,时区=用户设备;模拟浏览器时区必须用「+8 平移 + getUTC*」,`new Date()`+`getFullYear` 是进程时区。
- **结论**:后端固定 +8 后,前端浏览器 +8 天然对齐;仅浏览器时区≠+8(跨时区访问)才需前端配合。详见 `docs/问题记录/时区分析教训-浏览器时区与进程时区.md`。

- **现象(v1.4.29/30)**:Docker 容器部署后——趋势图缺某天(8/3 被算成 8/2)、今日已用异常(800 多)、页面左上角时间显示 8/4 16:47(实际本地 8/5 00:47);Windows 桌面(+8)全对,形成"edge 对、docker 错"。
