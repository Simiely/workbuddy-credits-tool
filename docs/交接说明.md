## 1. 项目是什么

多账号采集 WorkBuddy 积分并可视化。核心洞察:**积分包本身静态(总量/到期不变),变化的是"消耗"**——系统围绕"剩余积分变化"建模(SQLite 时序快照 + 柱状趋势 + 今日已用 vs 昨日 + 近 1/2/3/7 天到期 + WebDAV 一键同步)。

- 仓库:`Simiely/workbuddy-credits-tool`(public)
- 当前版本:**v1.4.49**(CHANGELOG 有完整记录)
- 技术:Node ≥18 原生 ESM,**零第三方依赖**(含 `node:sqlite`);前端原生 HTML/CSS/JS 无框架
- 双入口:CLI(`wb-credits.mjs`)+ GUI(`wb-gui.mjs`),共享 `src/` 分层

## 6. 核心约定(动了会坏,务必遵守)

1. **总剩余口径 = 体验版基础用量 + 赠送积分**,前端/后端/历史快照/仪表盘必须一致
2. **子路径挂载**:`__BASE__`(平台注入或自行检测),API 用 `__BASE__ + "/api/.."`,资源用相对路径
3. **daemon 发现**:CDP 标准(`/json/version`),勿改回读 DevToolsActivePort 文件
4. 前端 7 文件**实时读文件** → 改前端刷新即可;改 `wb-gui.mjs`/`src/*` 才需重启;改前端必须 bump 版本戳
5. 刷新超时:服务端单账号 8s、前端 12s;按钮状态单点控制,`finally` 必恢复
6. **统一采样入口** `sampleAll()`:新增写 readings 的路径必须复用,不要另起炉灶
7. **凭证安全**:push 前确认 `git status` 无数据文件(wb-accounts/wb-sync/wb-admin/credits.db/edge-daemon.token)
8. **前端文件清单改动同步 4 处**:html 引用 / wb-gui.mjs 静态路由 / server-routes 测试 / vm-env 文件列表
9. **消耗口径(包级)**:`consumeByPack` 只统计末快照 active 包的 used 增量——**每天首条+末条快照必须带 giftPackages**,否则降级增量口径(今日已用虚高)。备份剥离策略(v1.4.47)已保证每天首末保留,勿改回"只留最新组"
10. **一键同步**(v1.4.46):先拉(账号 smart 合并 + 历史合并导入)→ 再传(导出全量覆盖);404=首次只传;拉取失败中止不上传;**清空保护**——远端有账号但合并后本地为空 → 拒绝上传
11. **墓碑(v1.4.46)**:删除账号(/api/del)写 tombstones(uin+deletedAt)随备份传播防复活;**清空账号池(/api/clear-data)不写墓碑**(本地重置不传播删除,v1.4.48);TTL 30 天清理
12. **同步/测试前端超时**(v1.4.49):syncAct 按动作放宽——sync=90s、test=30s(后端下载/上传各 60s)
