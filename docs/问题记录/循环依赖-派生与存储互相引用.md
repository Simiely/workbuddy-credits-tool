# 问题:derive↔history 循环依赖(派生层与存储层互相 import)

**TL;DR**:`history.js` 为提供 `buildDashboard` 而 `import deriveAll`(derive.js),同时 derive.js 又 import history.js 的读取/固化函数 → 真环。ESM 靠运行时惰性求值勉强跑通,但增加理解成本、动 import 易踩 hoisting 坑。

- 问题:`src/compute/derive.js ↔ history.js` 互相 import(derive L14 import history 8 个函数;history L126 import derive 的 deriveAll),与"collect→compute→store"单向分层声明矛盾
- 根因:① 历史固化 `gcDaySummaries` 为了复用 consumeByPack/detectSignIn 放在 derive.js,被迫 import history 的写库函数;② history.js 里的 `buildDashboard`(装配派生视图)为省一次调用直接 import deriveAll——两个方向各加一根"回引",环闭合
- 解决(v1.4.58):
  1. 时区工具抽到 `src/time.js`(TZ_MS/cnNow/dayKeyOf/dayOfOffset/startOfToday),消除各文件重复口径
  2. 历史固化拆到 `src/compute/gc.js`(`gcDaySummaries`),依赖 derive+history+time **单向**
  3. 删除 history.js 无调用方的 `buildDashboard` 及 `import { deriveAll }` → **环断开**,history 不再依赖 derive
- 预防:
  - 依赖方向铁律:collect→compute→store + time/gc(单向);**任何模块不得 import 上游**
  - "装配/编排"函数(如 buildDashboard)不该躺在存储层——放调用方或独立模块
  - 写库逻辑(固化/GC)不要塞进"纯派生"文件(名不副实,先例:derive.js 头注释"纯函数"却写库)
- 相关:v1.4.58;验证:npm test 12/12(含 gc-summary/signin-detect 改引 gc.js)
