# 部署指南（P5）

两种部署方案共享同一套 `src/compute`（查询/派生/采样）与 `src/present`（渲染），
差异仅在采集入口（`src/collect`，由 `WB_COLLECTOR` 或平台决定）：

| 方案 | 采集入口 | 适用 | 启动方式 |
|------|----------|------|----------|
| 桌面 | Edge CDP 常驻代理（edge） | Windows 本机，Edge 已登录 | 双击 `wb-gui.bat` |
| 容器 | 文件/WebDAV 同步（file） | Docker / NAS / Linux | `docker compose up -d` |

## 桌面方案（Windows）

1. 安装 Node.js 22+（或把可用的 node.exe 加入 PATH）。
2. 双击 `wb-gui.bat`（脚本用 `%~dp0` 定位项目目录，可放任意位置）。
3. 浏览器打开 <http://127.0.0.1:8080>；保持 Edge 处于登录态（Edge CDP 采样）。
4. 关闭窗口即停止服务。

## 容器方案（Docker）

```bash
docker compose up -d      # 一键起，打开 http://127.0.0.1:8080
docker compose logs -f    # 看日志
docker compose down       # 停止（数据留在宿主机）
```

- 采集走 `WB_COLLECTOR=file`（WebDAV 同步），不需要 Edge。
- 数据文件（`wb-accounts.json` / `wb-sync.json` / `wb-admin.json` / `credits.db`）
  **不打包进镜像**（见 `.dockerignore`，防凭据入镜像），
  由 compose 的 `.:/app` bind mount 从宿主机读写。

## 数据互通

两种方案共用**同一份数据文件**（都位于项目根目录）：

- `wb-accounts.json` —— 账号池（含会话凭证）
- `wb-sync.json` —— WebDAV 同步配置
- `credits.db` —— SQLite 时序快照（readings）+ 本地缓存

桌面与容器切换时无需迁移：谁拿到同一目录，谁就用同一份数据。

## 环境变量（均可选，默认值见 src/config.js）

| 变量 | 默认 | 说明 |
|------|------|------|
| `WB_COLLECTOR` | 平台自动（win32=edge，其余=file） | 强制指定 `edge` 或 `file` |
| `TZ` | 容器内 Asia/Shanghai | 已写入 Dockerfile/docker-compose（时区双保险） |

> 注：告警相关变量（`WB_ALERT_*`）已随告警模块下线（v1.4.15），不再存在。
> 注：程序内自然日/时间显示**固定中国时区(+8)**（v1.4.29/30），不依赖 `TZ`；`TZ` 仅作容器环境兜底。

## 验收

- [ ] 桌面：双击 `wb-gui.bat` 起服务、浏览器可开、Edge 采样正常
- [ ] 容器：`docker compose up -d` 一键起、浏览器可开、WebDAV 同步后出数据
- [ ] 互通：桌面/容器指向同一目录时数据一致（同一份 wb-*.json / credits.db）
